CivicOps Mumbai: who owns the problem, when it is due, and proof it was fixed

A resident reports a civic problem, CivicOps routes it to the right ward and team with a live deadline, and a super admin closes it only on photo evidence. The same app follows every rupee in the organiser's repair data: complaint → work order → bill vs rate card → did the fix hold → where the next rupee should go.

Super admin
VerifySide-by-side photos + Claude assessment (advisory). Approve, request evidence, or return for rework, always with a reason.
→
Resident
Green · 100%Full timestamped history in IST; can reopen within 30 days

Missed deadlines escalate automatically (one alert per threshold, even on retries). Permissions are enforced inside the database: residents see only their tickets, officers only their ward and department, and only a super admin can close.

3 · Judging criteria → what we show

25%
Audit accuracy
  • Threshold set from the data: normal band ≤ 1.32×, flags > 1.35×
  • Double billing, DLP paid, missed SLA and reopened, each with a one-line reason
20%
Fair accountability
  • Rain during the job shown next to every delay
  • Reopen rate vs expected for the methods used
  • "Review signals, not findings"
20%
Budget smarts
  • Next-rupee ranking per ward with reasons
  • Cost per lasting fix, not cheapest patch
  • DLP roads claimed from the contractor
15%
Connects the trail
  • Complaint → issue → work order → bill → durability
  • Messy multilingual input handled, originals kept
20%
Usable + demo
  • Resident phone flow, officer queue, admin review
  • "What happened to my complaint?" in plain words
